# Описание датасета

В этом соревновании вам предстоит работать с временными рядами электромиографии (ЭМГ) и движений пальцев кисти.

Датасет содержит записи электрической активности мышц предплечья и соответствующие им углы суставов. Ваша задача — построить модель, которая по сигналам ЭМГ сможет предсказывать эти углы.

Данные получены от одного участника в разные дни и в нескольких сеансах записи. Это позволяет исследовать не только качество предсказаний на знакомых данных, но и способность модели работать с новыми записями.

## 1. Как устроены данные

Каждая запись представляет собой отдельный временной ряд с частотой дискретизации около **500 Гц**.

Для обучающих записей доступны два массива:

| Данные | Форма массива | Описание                                    |
| ------ | ------------- | ------------------------------------------- |
| ЭМГ    | `(T, 6)`      | Шесть каналов электрической активности мышц |
| Углы   | `(T, 20)`     | Двадцать углов суставов кисти в радианах    |

Здесь `T` — количество временных отсчётов в записи.

Каждая строка массива ЭМГ соответствует одному моменту времени и содержит шесть значений — по одному на канал.

Соответствующая строка массива углов содержит положение пяти пальцев в этот же момент времени.

**Важно:**

* Массивы сохранены в формате NumPy `.npy` с типом `float64`.
* Для обучения нейросетей можно преобразовывать данные в `float32`.
* Сигналы ЭМГ уже прошли базовую предварительную обработку. Исходные необработанные записи в пакет не входят. Участники на свое усмотрение могут сделать дополнительные шаги предобработки.
* Порядок шести каналов одинаков внутри каждого массива, но соответствие каналов конкретным электродам не предоставляется.
* Записи имеют примерно по 20 500 отсчётов (около 41 секунды). Точная длина определяется размером массива.

## 2. Структура файлов

Данные предоставляются в двух пакетах, соответствующих этапам соревнования.

После распаковки обоих пакетов в общую папку структура будет следующей:

```text
data/
├── train/
│   ├── signals/
│   │   ├── rec_....npy
│   │   └── ...
│   ├── targets/
│   │   ├── rec_....npy
│   │   └── ...
│   ├── metadata.csv
│   └── angle_info.json
│
├── phase1_test/
│   ├── rec_....npy
│   └── ...
│
├── test/
│   ├── rec_....npy
│   └── ...
│
├── phase1_sample_submission.csv
└── phase2_sample_submission.csv
```

Папка `test/` и файл `phase2_sample_submission.csv` становятся доступны на втором этапе.

### Обучающие данные — `train/`

Обучающая выборка содержит **80 записей**, для каждой из которых доступны:

* `train/signals/` — массив ЭМГ формы `(T, 6)`;
* `train/targets/` — соответствующий массив углов формы `(T, 20)`.

**Сигналы и углы сопоставляются по имени файла.**

Например:

```text
train/signals/rec_abc123.npy
train/targets/rec_abc123.npy
```

Эти файлы относятся к одной записи. Их первые измерения (`axis=0`) соответствуют одним и тем же временным отсчётам.

Идентификаторы файлов анонимизированы и сами по себе не несут информации о движении, дне или сеансе.

## 3. Метаданные обучающей выборки

Файл `train/metadata.csv` содержит дополнительную информацию о каждой обучающей записи.

| Столбец        | Значение                                                         |
| -------------- | ---------------------------------------------------------------- |
| `recording_id` | Идентификатор записи, совпадающий с именем `.npy` без расширения |
| `day_id`       | Анонимный идентификатор дня записи                               |
| `session_id`   | Анонимный идентификатор сеанса                                   |
| `action`       | Название выполняемого движения                                   |
| `n_samples`    | Количество временных отсчётов                                    |

В данных представлены восемь типов движений:

| Движение | Описание                      |
| -------- | ----------------------------- |
| `Index`  | Движение указательного пальца |
| `Middle` | Движение среднего пальца      |
| `Ring`   | Движение безымянного пальца   |
| `Little` | Движение мизинца              |
| `Thumb`  | Движение большого пальца      |
| `Fist`   | Сжатие кисти в кулак          |
| `Open`   | Раскрытие кисти               |
| `Close`  | Закрытие кисти                |

Метаданные можно использовать для анализа данных, организации обучения и валидации.

Особенно полезно различать **сеансы и дни записи**:

* Одинаковый `session_id` означает принадлежность записей к одному сеансу.
* Одинаковый `day_id` означает, что записи были сделаны в один день.
* Разные сеансы могут относиться к одному дню.
* Идентификаторы анонимны и не задают хронологический порядок.

При проверке качества модели рекомендуется разделять данные по сеансам или дням, а не случайно перемешивать отдельные временные отсчёты.

Так вы сможете лучше оценить способность модели работать с новыми записями.

## 4. Порядок углов суставов

Каждый целевой отсчёт содержит **20 значений** — по четыре угла для каждого из пяти пальцев.

Точный порядок приведён в `train/angle_info.json`.

| Столбцы               | Палец                |
| --------------------- | -------------------- |
| `angle_00`–`angle_03` | Указательный (Index) |
| `angle_04`–`angle_07` | Средний (Middle)     |
| `angle_08`–`angle_11` | Мизинец (Little)     |
| `angle_12`–`angle_15` | Безымянный (Ring)    |
| `angle_16`–`angle_19` | Большой (Thumb)      |

Для каждого пальца порядок четырёх углов одинаков:

1. `mcp_theta`
2. `mcp_fi`
3. `pip`
4. `dip`

`MCP` соответствует суставу у основания пальца (для него представлены две угловые компоненты), а `PIP` и `DIP` — следующим суставам пальца в используемой модели кисти.

Обратите внимание: **мизинец идёт перед безымянным пальцем**. Не следует предполагать другой порядок пальцев.

Все углы измеряются в **радианах**.

Целевые значения находятся в диапазоне от −π до π. При этом метрика сравнивает численные значения углов напрямую, поэтому предсказания, отличающиеся на полный оборот (2π), не считаются эквивалентными.

Порядок углов можно учитывать при разработке модели — например, использовать отдельные выходные блоки или функции потерь для разных пальцев.

## 5. Как загрузить данные в Python

Для чтения файлов достаточно NumPy и любой библиотеки для работы с CSV, например pandas.

```python
import numpy as np
import pandas as pd
from pathlib import Path

data_dir = Path("data")

metadata = pd.read_csv(data_dir / "train/metadata.csv")

recording_id = metadata.iloc[0]["recording_id"]

emg = np.load(data_dir / "train/signals" / f"{recording_id}.npy")
angles = np.load(data_dir / "train/targets" / f"{recording_id}.npy")

print("EMG:", emg.shape)
print("Angles:", angles.shape)
```

Ожидаемые формы:

```text
EMG:    (T, 6)
Angles: (T, 20)
```

При подготовке данных для PyTorch обратите внимание на порядок измерений: многие модели, например `torch.nn.Conv1d`, ожидают форму `(batch, channels, time)`, а исходные массивы имеют форму `(time, channels)`.

## 6. Тестовые данные

### Этап 1 — `phase1_test/`

На первом этапе доступны **8 небольших синтетических записей ЭМГ**.

Каждый файл содержит искусственно сгенерированный сигнал формы `(1008, 6)`.

Правильные углы для этих записей также сгенерированы искусственно и не предоставляются участникам.

Этот набор предназначен для технической проверки:

* корректно ли модель загружает тестовые файлы;
* правильно ли формирует предсказания;
* совпадают ли идентификаторы и временные индексы;
* принимает ли платформа итоговый CSV-файл.

**Результат на синтетическом тесте не отражает качество модели на реальных записях.**

Для сравнения моделей используйте собственную валидацию на обучающих данных.

### Этап 2 — `test/`

На втором этапе становятся доступны **32 реальные тестовые записи ЭМГ**.

Формат входных данных тот же, что и при обучении: массивы `(T, 6)`.

Но для тестовых записей не предоставляются:

* правильные углы суставов;
* названия выполняемых движений;
* идентификаторы дней и сеансов.

Модель должна сформировать предсказания по доступным сигналам ЭМГ.

## 7. Первые 1000 отсчётов и формат предсказаний

Для каждой тестовой записи первые **1000 отсчётов (около 2 секунд)** не участвуют в расчёте метрики.

Они остаются в массиве ЭМГ и могут использоваться моделью как начальный контекст.

Предсказания необходимо предоставить для всех индексов:

```text
1000, 1001, 1002, ..., T-1
```

Для каждого такого индекса нужно предсказать 20 углов.

### Формат CSV

Для каждого этапа предусмотрен собственный образец:

* `phase1_sample_submission.csv`
* `phase2_sample_submission.csv`

Файл предсказаний должен содержать следующие столбцы:

```text
row_id,recording_id,sample_index,angle_00,...,angle_19
```

Их назначение:

| Столбец               | Описание                                     |
| --------------------- | -------------------------------------------- |
| `row_id`              | Уникальный идентификатор строки предсказания |
| `recording_id`        | Идентификатор тестовой записи                |
| `sample_index`        | Временной индекс внутри записи               |
| `angle_00`–`angle_19` | Предсказанные значения 20 углов в радианах   |

**Необязательно изменять непосредственно файл-образец:** ваша программа может создать новый CSV с нуля.

Главное, чтобы он содержал все требуемые строки и правильно связывал `row_id`, `recording_id`, `sample_index` и предсказанные углы.

Для надёжности рекомендуем сохранять порядок строк и три идентификационных столбца из образца без изменений, заполняя только значения углов.

Все предсказания должны быть конечными числами — без `NaN`, `Inf` и пропущенных значений.

Не добавляйте дополнительные столбцы.

## 8. Рекомендации для разработки

Несколько практических идей, которые могут пригодиться:

1. **Начните с визуализации.** Постройте графики нескольких каналов ЭМГ и соответствующих углов пальцев. Посмотрите, как меняются сигналы при разных движениях.
2. **Учитывайте временной контекст.** Отдельный отсчёт ЭМГ содержит ограниченную информацию. Попробуйте использовать окна соседних отсчётов, признаки сигнала или модели для временных рядов.
3. **Следите за масштабом каналов.** Нормализация ЭМГ может помочь обучению. Рассчитывайте её параметры только по обучающей части соответствующего разбиения, чтобы не допускать утечки информации из валидации.
4. **Проверяйте обобщение на новые сеансы и дни.** Высокое качество на случайно выделенных фрагментах знакомой записи не гарантирует хорошего результата на независимых записях.
5. **Анализируйте ошибки отдельных пальцев.** Поскольку углы сгруппированы по пальцам, можно отдельно изучать качество предсказания каждого из них.
6. **Сначала проверьте весь путь до CSV.** Даже простая модель полезна как отправная точка, если она правильно обучается, работает с тестовыми массивами и формирует файл нужного формата.

Вам не обязательно использовать какой-то определённый подход. Можно экспериментировать с классическими методами машинного обучения, признаками ЭМГ, свёрточными нейронными сетями и другими архитектурами.

Главное — корректно оценивать качество своих решений и помнить, что итоговая задача состоит в предсказании движений на новых записях.
